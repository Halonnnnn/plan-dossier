# Plan Dossier

**Language / 语言**: [English](../README.md) | [中文](README.md)

一套面向跨阶段长任务的 `.plan-dossier/` 工件规范与工作流：规划、执行、审查三个阶段共享按失效方式划分的四层工件，消除执行阶段的二次检索与二次规划，同时保持审查阶段的独立性。

完整技能定义见 [SKILL.md](SKILL.md)。

---

## 问题背景

Planner → Executor 是多 Agent 协作与可恢复工作流的主流模式：强推理模型规划，产出一份 `plan.md`，其他 Agent 读它分步执行。问题不在流程，而在工件：**我们把面向人类的渲染视图直接当成了面向机器的执行态。**

计划文档是对整个探索过程的一次高损耗的有损压缩，执行方能读到的只有文字，规划阶段最宝贵的中间认知全部丢失：

- **负向知识丢失。** Planner 评估过方案 A、B、C，因某个隐性依赖排除了 A 和 B 才选 C，但计划里只写"采用方案 C"。Executor 遇到阻力时要么重新调研浪费 token，要么自作聪明改回方案 A 直接踩坑（二次规划）。
- **原始锚点丢失。** Planner 读过具体行号、接口签名、原文数据，写进计划时变成"参考现有鉴权逻辑进行改造"。Executor 拿到结论式摘要，除了重新 grep 无从下手（二次检索）。
- **动态状态丢失。** 静态计划无法承载执行期的偏离与发现，流程中断后难以精准恢复。

出路不是把计划写得更长（每次交接都重复付费、投影仍有损、频繁变更失可信），而是拆分：**定位进账本，动态状态进交接层，渲染视图给人类**——每层用与其失效方式匹配的手段校验。

## 安装

本 skill 是纯文件，无运行时依赖，任何能读取 SKILL.md 的 agent 环境均可使用。

### 手动安装

```bash
git clone <本仓库> /tmp/plan-dossier
mkdir -p ~/.agents/skills/plan-dossier
cp /tmp/plan-dossier/zh-CN/SKILL.md ~/.agents/skills/plan-dossier/SKILL.md
```

重启 agent 会话以发现 skill，之后通过"要求输出计划"触发。

### 其他环境

- **Claude Code 及其他 agent CLI**：将 `SKILL.md` 复制到对应 skill 目录（如 `~/.claude/skills/plan-dossier/`），保留 `name:` frontmatter。
- **作为仓库约定**：把 `SKILL.md` 提交到仓库根目录（或链接本仓库），让同一仓库中的所有 agent 共享同一份 `.plan-dossier/` 规范。

中文版位于本目录的 [SKILL.md](SKILL.md)；英文版位于根目录 `SKILL.md`。skill 产出的 YAML/JSONL 工件与语言无关，两种语言版本效果一致。

## 工作原理

一轮完整工作流，以及各阶段读写哪些工件：

```text
          写入                        写入
planner ───────► L0 plan.yaml ──── 冻结 ─────┐
   │  （探查仓库，                            │ packet 组装
   │   追加 L2 账本）                         ▼
   │                             ┌──────── executor ────────┐
   │                             │ 读取：plan.yaml、账本目录、│
   │                             │ 自己的任务卡              │
   │                             │ 写入：dag[].status、      │
   │                             │ handoff/NN_to_MM.md      │
   │                             └──────────┬───────────────┘
   │                                        │ （逐节点循环，直到 DAG 完成）
   └── L1 任务卡 ──► tasks/*.yaml           ▼
                                 审查 ◄── views/review.packet.md
                                 （隔离：无计划、无账本，
                                   重读变更文件独立判断）
```

关键机制，各一行：

- **L0 + L1 在审批通过时冻结。** 冻结部分字节稳定，跨交接、跨模型切换都能命中 prompt 前缀缓存。修改走版本升级并归档旧文件；`dag[].status` 回写是唯一的运行时变更，同时是断点续传入口。
- **L2 账本只追加。** 条目只存定位与结论（不存源码内容）、成本和 `verdict: relevant | excluded | unknown`。修订追加新行并写 `supersedes`。region_sha 让片段加载时的校验足够便宜。
- **L3 交接三段齐全**——Actual Outputs、Deviations、State Snapshot——新会话凭真实产物路径和已知过期条目接续，不靠复选框。
- **packet 按角色裁剪，预算 4K tokens**：稳定内容在前（plan.yaml、账本目录）保护前缀缓存；超预算先截账本目录，`excluded`、`constraints`、`risks`、`gaps` 不截。
- **审查隔离**：审查方只拿原始需求、差异和变更文件前后全文。前序结论恰恰是最容易错的部分，审查方绝不接触。
- **信任可重放，不靠声明。** 每条 `trust: checked` 事实都带 `assertion.replay`——规划方实际执行过的命令——任何消费方都能以一条命令的成本重新验证该结论。
- **防回退显式化。** `excluded` 记录排除了什么、为什么（冻结常驻）；`risks` 把每条风险映射到设防的验收条目（`mitigated_by` 锚点）；`gaps` 声明计划刻意留给执行方自行判断的维度。
- **只管规划侧。** skill 负责编写工件并定义其语义；执行、校验、恢复、审查的工作流属于下游 agent。resume 是可选项：断点存在，维护与否由下游决定。

## 架构

```text
.plan-dossier/
├── plan.yaml              # L0 冻结全局契约：目标/约束/验收/DAG/决策/排除项/风险/边界声明
├── tasks/                 # L1 任务卡：每卡一个节点，执行器只加载自己那张
│   ├── 01_extract_validator.yaml
│   └── 02_replace_callers.yaml
├── ledger.jsonl           # L2 检索账本：只追加，记录定位/结论/成本
├── handoff/               # L3 执行期交接：上游执行器写，下游执行器读
│   └── 01_to_MM.md
└── views/                 # 编译产物，可删除可重建，不是事实源
    ├── plan.view.md       # 人类审阅视图（由 L0 + L1 渲染）
    └── review.packet.md   # 审查隔离视图（交接审查时编译）
```

每层绑定一种失效方式，决定其变更规则与校验手段：

| 层 | 工件 | 读取方 | 变更规则 | 校验方式 |
|---|---|---|---|---|
| L0 | plan.yaml | 所有角色常驻 | 冻结，修改即升版本归档 | 人工判断 + schema 检查 |
| L1 | tasks/*.yaml | 仅对应执行器 | 随 L0 一起冻结 | cites 引用存在性检查 |
| L2 | ledger.jsonl | 规划/执行按需 | 只追加，修订用 supersedes | region_sha 惰性比对（可选） |
| L3 | handoff/*.md | 下游执行器 | 每完成一步追加 | 以最新一份为准 |
| views | *.md | 人类/审查 | 随时重建 | 派生物，无需校验 |

交接时按角色裁剪可见内容：

| | plan.yaml | 任务卡 | 账本目录 | excluded | 源码片段 | unverified 结论 |
|---|---|---|---|---|---|---|
| 规划 | 全量 | 全量 | 目录 + 按需 | 全量 | 按需 | 全量 |
| 执行 | 全量 | 仅自己的卡 | 目录 + 按需 | 全量 | 按需 | 全量 |
| 审查 | 不提供 | 不提供 | 不提供 | 不提供 | 变更文件前后全文 | 不提供 |

预算规则：L0 不超过 2K tokens，单张任务卡不超过 1K，交接包不超过 4K；截断时先截账本目录再截 open_questions，`excluded`、`constraints`、`risks`、`gaps` 不截。交接包的组装顺序即 prompt 拼装顺序：稳定内容在前（系统提示、plan.yaml、账本目录），易变内容在后（当前任务卡、handoff、按需片段），以保护前缀缓存。

工件组织由两个维度决定——被读取频率和内容变更频率。高读取、低变更的内容（计划）必须短且冻结；低读取、高变更的内容（账本、交接）不限长度、按需加载。

## 为什么"把计划写得更详细"走不通

最直觉的方向，也是走不通的方向：

1. **重复付费。** 计划的读取次数等于角色数乘以轮次。从 1.5K 加长到 20K，等于每次读取都多付 18.5K，其中大部分对当前阶段无用。
2. **投影不可逆。** 计划是探索过程的有损投影，加长只提高投影分辨率。把搜索结果写成文字描述是对内容的二次转述，精度低于直接记录位置。
3. **频繁变更失可信。** 计划越长越难维持，内容频繁变更的文档会失去可读性，最终连"决策记录"这个作用也保不住。

所以本规范的方向不是加长计划，而是把计划不适合承载的信息分离出去，交给专门工件：定位进账本，动态状态进交接层，渲染视图给人类。

## 为什么现有机制不够

| 机制 | 已解决 | 未解决 |
|---|---|---|
| Prompt Caching（各厂商） | 同模型、同前缀的计算复用 | 跨模型、跨厂商；不涉及"该读什么" |
| hashline 类哈希锚定编辑 | 编辑落点错误被拒绝 | 锚点随会话结束失效；不记录搜索历史，对二次检索无作用 |
| RAG | 相似度检索 | 不记录已作出的判断（相关/排除）与获取成本 |
| Agent Memory | 历史信息保存 | 摘要失真、无法校验、缺少失效处理 |

这些机制各自成立，但都不产生"可复用的获取结果和检索判断"。重新搜索的主要成本在判断，不在查找——这正是账本要持久化的东西。

## 设计沿革

本规范由两组独立产出融合而成：四层目录形态（渐进披露的 `.plan-dossier/`、按节点任务卡、DAG 并行、三段式 handoff、稳定前缀 packet 排序），以及校验机制（重读分类、按失效方式分工件、获取成本记录、信任分级、三级失效处理、审查隔离、packet 预算、可证伪预测）。关键融合决策及理由：

| 来源概念 | 处置 | 理由 |
|---|---|---|
| v1 anchors.md（verbatim 摘录） | 改造为 ledger.jsonl，只存定位与结论，不存内容 | verbatim 内容会静默过期且无检测手段；只存 locator 则内容按需加载，配合 region_sha 惰性校验 |
| v1 decisions.md（负向知识） | 拆分：一行式排除项进 L0 excluded（冻结常驻），详细踩坑进账本 verdict=excluded 条目 | 设计文档预测排除项收益最大（E1 > E3），防回退信息必须冻结常驻 |
| v1 plan.md（L0） | 改为 plan.yaml 单源 + views/plan.view.md 渲染 | 单一事实源，cites 引用存在性可校验，不手工维护两份 |
| v2 steps 内联 plan.yaml | 移入 L1 任务卡 + cites 引用制 | 多执行器上下文隔离；修复 v1"L1 抄写 L2"的不一致 |
| v1 前缀缓存拼装顺序 + v2 交接包预算 | 合并为同一机制：packet 排序规则 = prompt 拼装顺序 | 一体两面：v1 讲顺序、v2 讲预算与裁剪 |
| v2 片段缓存 blobs/、blob_sha | 不纳入规范正文，归运行时支持一节 | skill 是文件规范，blob 存储属工具层，无运行时支持时空转 |
| v2 信任分级、三级失效、supersedes 修订 | 全部保留 | 生产级可校验性的核心 |
| v1 DAG 状态表 | 保留在 L0 | 断点续传入口 |
| 命名体系 | ANC-xx / DEC-xx / L-xxxx 统一为账本条目 L-xxxx | 消除两套 ID 体系 |

首次实测反馈驱动了七项打磨，均已并入正式规范：

- **形态确认。** `.plan-dossier/` 落盘与否、`plan.view.md` 渲染与否改为向用户确认的选项，不再由特征单方面判定；最简形态默认不渲染视图，审批直接看 plan.yaml。（后续修订：形态改为自动判定并一句话说明理由，仅在范围确实不明确时提问。）
- **risks 覆盖检查。** L0 新增 `risks` 字段，`mitigated_by` 用锚点（`aN`、`sM.N`）引用 acceptance 条目，引用完整性检查覆盖风险到用例的映射。
- **计划内单一来源。** 同一数据清单在 L0 与任务卡中只在一处展开，他处用锚点或 ID 引用。
- **gaps 边界声明。** L0 必填 `gaps`（可为空），显式列出计划未覆盖的判断维度，与 `open_questions`（待裁决问题）语义分离；与 `risks` 同入 packet 不截名单。
- **assertion 可重放。** `trust: checked` 的断言改为可原样执行的 replay 命令，规划方标注前必须实际执行，执行方依赖该结论前惰性重放。
- **views 读者限定。** `plan.view.md` 只面向人类审批者，执行方输入不含 views。
- **base.env。** 环境事实（构建前置、基线既有失败）进 L0 base 常驻，过期经 handoff State Snapshot 告知。


## 评测与可证伪预测

评估同时报告四项：重复获取比例、搜索到首次编辑的工具调用次数、任务通过率、失效后的错误使用率。单看任何一项都会被误导——全部作废也能让"失效识别率"达到 100%。

设计包含一条可证伪预测：排除项（E1）的收益应大于片段复用（E3）。实测相反则说明执行方缺的主要是内容而非定位信息，架构重心应从检索结论转向内容缓存。评估必须设两个对照：等 token 对照（给基线同样的额外预算，内容写成普通描述）和计划长度对照（记录计划文档长度，确认收益不来自计划变长）。

实测结果（多轮单执行器，完整形态）：净省估算为会话上下文的 30-40%，方向性偏离 0，零返工。小任务/小项目效果不高，在大型项目长任务上效果明显。

## 快速上手

1. 读 [SKILL.md](SKILL.md)。触发后按任务特征自动判定工件形态（完整 / 最简 / 纯文本）与是否渲染视图，并用一句话说明判定理由；仅在范围确实不明确时向用户提问，再按工件规范与工作流执行。
2. 规划阶段结束的标志：L0、L1 冻结，账本就位，审批对象（渲染视图或 plan.yaml）通过审批。
3. 执行按下游 agent 自己的工作流进行；dossier 承载其状态：dag[].status 是断点续传入口，handoff 记录产出、偏离与状态快照。
4. 审查阶段：编译 review.packet.md——只含原始需求、diff、变更文件前后全文与验收标准；审查流程由审查方自行决定。
